# GMGN 式 Meme 币交易系统 · 低成本方案 v1

> ⚠️ **本文档的第 3~5 节已被 [02-tools-and-repos-research.md](02-tools-and-repos-research.md) 取代**（GMGN 官方 OpenAPI 实测可用，数据层不再需要自建）。其余部分仍然有效，作为 Plan B。
> 原则：**先花时间，后花钱；先用免费数据验证 edge，再投入基础设施。**
> 所有价格/费率均为量级参考，会随平台政策变化，落地前以官网为准。
> 目标：用尽可能低的构建成本，做一个「发现新币 → 过滤风险 → 快速买卖 → 记账」的系统，并以赚钱为目的。

---

## TL;DR 决策摘要

| 决策 | 选择 | 理由 |
|---|---|---|
| 链 | 只做 **Solana** | Meme 流动性 90% 在这里；多链是 3 倍成本、0 倍早期收益 |
| 形态 | **后端 + Telegram Bot**，暂不做 Web 前端 | 前端成本是后端的 3~5 倍，交易者本来就在 TG 里 |
| 语言 | **TypeScript 全栈** | Solana 生态 SDK 最全，AI 辅助开发最快，一个语言到底 |
| 数据 | 全部用**免费源**（PumpPortal + Helius Free + DexScreener + Jupiter） | 前 3 周 $0 |
| 基础设施 | 1 台 €4/月 VPS + 本地 Postgres | 月成本 <$10 |
| 策略 | **低频、高赔率**（每天 3~10 个候选，人工确认） | 摩擦成本 5~10%，高频小利数学上不可能赢 |
| 上线顺序 | 数据集 → 回测 → 告警 → 手动一键买 → 自动 | 每一阶段有 go/no-go，不盈利就停 |

**一句话结论**：这个系统最低可以做到 **$5~10/月 + 2~4 周业余时间** 跑起来；但真正决定赚不赚钱的不是系统，是「摩擦成本 < 你的平均收益」这一条数学。所以第一阶段必须做**零成本的数据集与回测**。

## 0. 先把赚钱逻辑说清楚（很重要）

GMGN 本身不靠炒币赚钱，它靠**收交易手续费**赚钱（约 1%，以官网为准）——它卖铲子。
你要复制的是它的**能力**（发现、过滤、执行、记账），不是它的**商业模式**。

一个自建系统的真实成本结构：

```
单次往返摩擦 ≈ 平台费(双边) + 优先费×2 + Jito小费 + 滑点(进场+出场) + 失败交易
           ≈ 2% + 0.2~1% + 0.05% + 3~8% + 0~1%
           ≈ 5~10%（小资金更差，因为固定费用摊不薄）
```

推论（这是整个方案的地基）：

1. **高频刷单必死**。每笔 5~10% 摩擦，你需要 60%+ 胜率才能打平，而 MEV 机器人比你快。
2. **只能做「大波动」**：目标 2~10 倍、止损 -30~50% 的机会，8% 摩擦可以接受。
3. 所以系统定位不是「全自动印钞机」，而是**「每天帮你筛出 3~10 个值得手动/半自动下注的机会」**。
   这恰好也让基础设施成本降到最低——低频不需要极致延迟。

> 这不是收益承诺。多数 meme 狙击者扣除费用后是亏的。本方案的价值是**用最低成本、最快速度让你自己验证有没有 edge**，而不是保证有。

## 1. 系统范围（MVP 做什么 / 不做什么）

**做**
- 新币实时发现（pump.fun 创建、毕业/迁移、新池子）
- 安全与质量过滤（权限、LP、持币集中度、创建者历史、bundle 迹象）
- 钱包情报（聪明钱/老鼠仓地址跟踪，自己算标签）
- 评分 + 告警（Telegram，带一键买入按钮）
- 执行（Jupiter / PumpPortal 本地交易 API，滑点与优先费控制）
- 持仓与 PnL 记账、风控（单笔上限、每日熔断）
- 回测/重放（用自己采集的数据）

**不做（一期）**
- Web 前端 / K 线图 / 社交功能
- 多链
- 自建撮合、自建节点
- 托管用户资金（合规红线，见 §8）
- 「保证收益」类信号群

## 2. 架构（单体 + Bot，够用且最便宜）

```
 PumpPortal WS ─┐
 Helius WS/RPC ─┼─▶ Ingestor ─▶ Normalizer ─▶ Enricher ─▶ Scorer
 DexScreener  ──┘   (原始事件)   (统一模型)    (安全/钱包)  (0~100 分)
                                                              │
                                                              ▼
                                                    Risk Manager ──▶ Executor
                                                   (仓位/熔断/限额)   (Jupiter/PumpPortal
                                                              │        + 优先费 + Jito)
                                                              ▼            │
                                                        Telegram Bot ◀─────┘
                                                       (告警/确认/一键买)
                                                              │
                                                              ▼
                                            Postgres（tokens / trades / wallets / signals / positions）
                                                              │
                                                              ▼
                                                     Replay & 回测（纯本地）
```

单进程 Node 服务 + 一个 TG Bot + 一个 Postgres，就够了。所有模块通过内存事件总线连接，不要一上来搞微服务/消息队列。

## 3. 数据源：全部用免费额度

| 数据 | 来源 | 成本 | 说明 |
|---|---|---|---|
| 新币创建 + 逐笔成交 | **PumpPortal WebSocket** | 免费 | 最划算的实时源；一个连接扇出给所有模块（限额需核实） |
| 链上事件/账户/交易 | **Helius Free**（约 1M credits/月） | $0 | 建 ws 订阅 + 按需查账户；超了就降频 |
| 兜底 RPC | QuickNode/Ankr 免费档 | $0 | 只做故障转移 |
| 价格/K 线/流动性 | **DexScreener 公开 API** | 免费 | 有限流，做「参考价」足够，别当主源 |
| 报价与兑换 | **Jupiter Quote/Swap API** | 免费 | 毕业后（Raydium/PumpSwap）走这里 |
| pump.fun 买卖 | **PumpPortal local trade API** | 免费 | 返回未签名交易，本地签名；省掉自己写曲线逻辑 |
| 安全报告 | **RugCheck API** + 自建规则 | 免费额度 | 自建规则更可控：mint/freeze 权限、LP 燃烧、Top10 占比 |
| 聪明钱标签 | **自己算**（见下） | $0 | 关键省钱点 |

### 省钱核心技巧：自己算聪明钱标签

GMGN 的「聪明钱」= 对全量钱包做历史 PnL 计算，很贵。低成本替代：

1. 你本来就在采集**全量新币 + 逐笔成交**（免费）。
2. 自己建一张 `token_outcome` 表：每个币在 t+30s / 5m / 1h / 24h 的价格与最大涨幅。
3. 回溯标记：某个钱包在「最终涨了 3 倍」的币上很早就买 → 加权重。
4. 得到你私有的 `wallet_score`，零 API 成本，只花 CPU + 一个晚上的 SQL。

这条路比订阅任何付费数据都便宜，而且**别人没有你的数据集**——这才是低成本下唯一可能的差异化。

## 5. 路线图（每阶段有 go/no-go）

### P0 · 数据集 + 纸面交易（第 1 周，$0）
- 接 PumpPortal WS，落库：新币、逐笔成交、毕业事件
- 每个币计算：t+15s/30s/60s/5m/1h 价格、最大涨幅、最大回撤、是否归零
- 验收：能回答「今天有多少比例的币从 t+30s 涨了 2 倍以上？它们的共同特征是什么？」
- **go/no-go**：数据完整率 >95%，且你能跑出第一版统计

### P1 · 特征 + 规则 + 回测（第 2 周，$0）
- 特征：创建者历史、前 10 持有者集中度、买入/卖出笔数比、独立买家数增速、LP 状态、社交信号（可选）
- 用 P0 数据做**样本外回测**（按天切分，禁止未来函数）
- 验收：找到一组规则，扣除 8% 摩擦后**样本外**期望为正
- **go/no-go**：找不到 → 停止投入，转「卖工具」路线（§6-A）；找到 → 进入 P2

### P2 · 告警 + 一键手动买（第 3 周，~$10/月）
- Telegram 推送：币名、评分、理由、K 线链接、一键买入按钮（Jupiter/PumpPortal 本地签名）
- 用小额真金白银（0.05 SOL）跑 100 笔，记录**真实滑点与失败率**
- **go/no-go**：真实成交价与回测假设偏差 <2%，否则修执行层

### P3 · 半自动/自动执行 + 风控（第 4~6 周，~$15/月）
- 仓位状态机（防重复买、防重试双花）、止盈止损、移动止损
- 风控：单笔上限、每日最大亏损熔断、黑名单、并发仓位上限
- 验收：连续 2 周实盘，PnL 与预期偏差可解释

### P4 · 延迟优化（只有「被延迟卡住」才做）
- gRPC 流、Jito bundle、靠近 RPC 地域的 VPS
- **不要提前做**：这一层每月多花 $100~400，而 95% 的情况下你的瓶颈是策略不是延迟

## 6. 钱从哪来（按风险从低到高）

**A. 卖铲子（工具/订阅）** — 风险最低
你的实盘记录 + 私有数据集就是护城河。先自用跑 1~2 个月，有正收益曲线后再考虑对外。
难点：获客。GMGN 有巨大网络效应，你只能做垂直细分（中文社区、特定策略、特定钱包跟单）。

**B. 聪明钱跟单** — 中等风险，本方案首选
edge：比人快、严格执行、只在钱包历史胜率高时跟。
失败模式：滞后 1~2 个块、被反向收割、跟到大户出货。

**C. 新币狙击/动量** — 高风险
edge：更快的信息或更早的发现。零售基本打不过专业 searcher，别把宝押在「首块狙击」。

**D. 做市/提供流动性** — 资金密集型
不是软件优势，是资金和风控优势，且有无常损失。不建议作为第一步。

**E.（不建议）收费喊单/带单** — 容易滑向虚假宣传与法律风险。

**推荐组合**：先 B（用 P0 数据集验证跟单钱包的质量）→ 若 B 成立则放大；若不成立转 A。

---

## 7. 风控（写进代码，不是写进脑子）

- **热钱包隔离**：专用钱包，只放当前要用的资金（≤$200），其余冷存
- **私钥**：AES-GCM 加密 + 环境变量口令；绝不进 git、绝不进日志
- **单笔上限**：0.05~0.15 SOL；**并发上限**：3 个仓位
- **每日熔断**：当日亏损达 -15% 自动停机，人工重启
- **黑名单**：mint/freeze 权限未放弃、LP 未燃烧、Top10 > 40%、创建者历史跑路 → 直接拒
- **滑点**：进场 10~15%，出场 20~30%（流动性差必须给足，否则卖不掉）
- **防双花**：仓位状态机 + 幂等键；重试前先查链上是否已成交
- **人工闸门**：P2 阶段全部人工确认；自动模式先只对「评分最高档」开放

## 8. 合规红线

- 不托管他人资金、不做资金池、不承诺收益（否则可能触及集资/支付牌照）
- 不做刷量、对敲、拉盘砸盘（wash trading / pump & dump），不做内幕交易
- 自托管钱包 + 明确风险提示；对外提供服务时保留免责声明
- 记录每笔交易，自行处理税务

## 9. 技术选型（为什么这套最便宜）

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node 20 + TypeScript | Solana SDK 生态最全（web3.js / jup / jito-ts） |
| Bot | grammY | 轻、快、类型好 |
| DB | Postgres（本地或 Supabase） | 关系型够用；时序量大再上 Timescale |
| 部署 | Docker Compose + 1 台 VPS | 一条命令起全套 |
| 监控 | 日志 + TG 告警 | 不买 Datadog |
| ML | 暂时不用；需要时 Python 单独脚本离线跑 | 在线推理用 TS 重写规则即可 |

**不要做的事**：买「GMGN 源码」（基本都是木马/骗子）；直接跑 GitHub 上的开源 sniper（多为过时教学代码，跑起来就亏）；一上来做 Web 前端。

## 10. 预期与止损线

| 情形 | 概率（主观） | 应对 |
|---|---|---|
| P1 找不到正期望策略 | 高 | 停止实盘，转工具路线，总损失 ≈ $0 |
| 找到但实盘打不过摩擦 | 中 | 降频、只做最高分信号，或放弃 |
| 小幅盈利（月 5~15%） | 中低 | 维持小规模，先跑 3 个月稳定性 |
| 大幅盈利 | 低 | 才值得投入 P4 延迟优化与更大本金 |

**投入上限建议**：$500 本金 + 3 个月业余时间。到线不复投、不借钱、不加杠杆。

## 11. 本周就能做的 5 件事

1. 申请 Helius 免费账号，拿到 RPC + WS endpoint（5 分钟）
2. 写 30 行脚本连 PumpPortal WS，把新币与成交打到 SQLite/Postgres（半天）
3. 建 `token_outcome` 表，写 SQL 算每个币 30s/5m/1h 的涨幅分布（半天）
4. 看一眼统计：**有多少币在 t+30s 之后还能翻倍**——这个数字决定项目生死
5. 如果数字乐观，再开始写评分与 TG 告警
